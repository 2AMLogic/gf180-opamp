# layout/first_stage — the amplifier's first stage as a placed sub-block (issue #328)

**Scope: a placed, labelled SUB-BLOCK — the five-device first stage only
(XM1–XM5 from `design/netlist/opamp_two_stage.spice`). This is NOT block
layout, NOT the full core (#241 keeps XM6/XM7/XCC/XRZ, the MIM
plate-orientation decision and the metal-stack decision record), NOT ERC,
parasitic extraction or post-layout simulation (#241, #279), and it makes **no
area claim and no T1 claim**. The 23.16 × 11.55 µm footprint below is the
placed bounding box of three generated cells with a 1 µm channel, not a
ratified or measured block area. `manifests/gf180-opamp.json` is not changed
by this directory.**

Everything here is regenerated by one command from a clean checkout; no cell
was edited by hand.

## What is placed, and why this way

`tools/first_stage.py` reads the five instance cards from the schematic and
generates three matched groups (`klt gen`, sizes derived from the cards —
nothing typed in):

| Group | Schematic | Generator and params (sizes = W/nf from the card) | Why |
|---|---|---|---|
| `in` | XM1, XM2 (`nfet_03v3` L=1u W=3.6u nf=2) | `diff_pair` w=1.8 l=1 splits=2, guard ring | common-centroid cross-quad: XM1 and XM2 each contribute one sub-instance to every column, so the two input legs interleave diagonally — the standard matched-pair style for an input pair |
| `load` | XM3, XM4 (`pfet_03v3` L=1u W=6u nf=2) | `diff_pair` w=3.0 l=1 splits=2, `mirror: true`, guard ring (draws the n-well tie) | same cross-quad for the mirror load; `mirror` labels the legs M1/M2 |
| `tail` | XM5 (`nfet_03v3` L=2u W=6u nf=2) | `mos_array` w=3.0 l=2 fingers=2, guard ring | the pilot's existing `w_um = W/nf` + `fingers = nf` mapping (`layout/pilot/tools/pilot.py`), which already LVS-matches on `pilot_nfet_mb1_m5` |

The `w_um = W/nf` + `splits = nf` mapping draws `nf` parallel unit strips per
leg — the same split the pilot uses for `mos_array` fingers, relying on the
LVS request's `combine_devices: true` + `compare_parameters` (W, L) to fold
the parallel sub-instances back to the schematic's total W. The pilot proves
that compare is live per device kind (its negative controls); the composed
cell inherits the same request options.

`klt gen-compose` places the three groups in one row (load, in, tail, 1 µm
channels) inside `gds/first_stage.gds`, with the groups' own guard rings/taps
and net-name pin labels: `VSS`/`IBIAS` at XM5's source/gate, `VSS` at the two
nfet ring taps (substrate ties) and `VDD` at the pfet ring tap (n-well tie).
Labels carry the schematic net names in the SPICE-reader's normalised upper
case (the same spelling `klt lvs` matches on). The multi-terminal nets
(`vdd`, `vinn`, `vinp`, `tail`, `n1`, `n2`) are declared as composition
connectivity; `vss` and `ibias` are single-terminal in this cut and are
labelled via `pins[]`.

**What this placement establishes: input-pair matching and mirror-load
matching only.** The bias mirror `XMB1/XM5/XM7` is cut by this slice — XM5's
placement is a lone tail device, NOT a matched mirror element; do not read it
as one (#241 places that group).

The sub-netlist (`ref/first_stage.klt.spice`) is cut mechanically from the
schematic — the five instance cards verbatim, continuation lines included —
with `.subckt first_stage vdd vss vinp vinn tail n1 n2 ibias`.

## Regenerate (one command, from a clean checkout)

```
layout/first_stage/regen.sh
```

Same identity gate as `layout/pilot/regen.sh`; refuses to run on any mismatch,
then rebuilds `gds/ ref/ extracted/ evidence/` and `results.json`.

| Item | Pinned identity |
|---|---|
| klayout-tools | `klt 0.8.0` (release; throwaway env first on PATH, e.g. `uv venv V && uv pip install --python V/bin/python klayout-tools==0.8.0 klayout==0.30.12 && PATH=V/bin:$PATH layout/first_stage/regen.sh`) |
| PDK | `gf180mcuD`, `open_pdks f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7` (`~/.ciel/gf180mcuD`) |
| klayout python / klt's engine | `0.30.12`, pinned explicitly (`PILOT_KLAYOUT_PIN`); `tools/first_stage.py` refuses the run on a mismatch |

Nothing is installed on the host; no ngspice is run.

Reproducibility, as measured on the pilot: **verdicts are stable across
regenerations, bytes are not** — KLayout stamps the wall-clock date into each
GDS, so the file's sha256 (and every content hash below it) moves per run.
`results.json` records each run's `layout_sha256` and asserts it equals the
`environment.layout_sha256` in the LVS envelope, which is the mechanical
"the checked layout is the layout this run produced, not an edited one"
check. Within a run that equality is exact; across runs compare verdicts, not
hashes.

- Every generator-drawn guard ring/tap and every placed label comes from the
  generator and the compose request — nothing is hand-drawn.

  the pin labels are mechanical (the compose response's `pins[]` is asserted

## The routing gap (why the deliverable is placed-only, and what it will cost)

AC 5 is **not met** by this slice, and the reason is a filed tool gap, not a
relaxed criterion.

- The placed deliverable above carries **no routing**: every inter-block and
  inter-unit net is declared as composition connectivity and validated, but
  drawing it is refused by `klt gen-compose`'s own spacing check.
- A full explicit-leg routing attempt (per-net routing planes, yard lanes,
  every leg written stub-aware) is regenerated into
  `evidence/first_stage.routed-attempt.{request,json,drc.klt.json}`: it
  connects five of the six multi-terminal nets (`tail`, `n1`, `n2`, `vinn`,
  `vinp`) and the sixth (`vdd`) is refused by the router's own check —
  `comes within 0.28um of ... metal2.space.1` — with two residual
  `metal4.space.1` violations on the drawn legs. This attempt is
  non-normative: it records what was placed and connectivity-validated.
- The refusal is structural, not tunable. `klt gen diff_pair` reports row
  pads at width-independent x columns with a **0.82 µm** inter-unit S↔D
  pitch; the router extends a fixed 0.28 µm stub from each port in the port's
  facing direction and lands a **0.42 µm** via-drop pad per metals level at
  every endpoint; two adjacent units on two different nets therefore end up
  0.82 − 0.28 − 0.14 − 0.21 = **0.19 µm** apart where the deck demands
  0.28 µm. The shortfall survives every net assignment, route width (already
  at the deck floor), routing-plane choice (the ladder stamps every level
  below the route plane) and block orientation (mirroring only swaps which
  pads face which way).
- Filed on klayout-tools, described generically:
  [#5764](https://github.com/2AMLogic/klayout-tools/issues/5764) (pitch/stub
  spacing) — the gap blocking AC 4's clean status for a *routed* block and
  AC 5's match; and
  [#5765](https://github.com/2AMLogic/klayout-tools/issues/5765) (layout-plan
  cannot fully wire a `splits ≥ 2` diff_pair, and the subckt-call digest
  splits instances into per-finger devices) — why the composition is driven
  through `klt gen-compose` with explicit connectivity rather than
  `klt layout-plan execute`, the curator-recommended verb: it was tried first,
  its connectivity derivation wires one generated port per declared digest
  device, and the digest has no per-instance device to declare — both verified
  against 0.8.0 before falling back (the curator's documented fallback
  condition). Sizes remain netlist-derived either way: the driver computes
  every `klt gen` parameter from the cards.
- Consequences for this slice, stated plainly: AC 1/2/3/4/6/7 are met by the
  placed deliverable; **AC 5's `status: match` is not met** — the committed
  `evidence/first_stage.lvs.klt.json` records `status: mismatch`
  (29 layout nets vs 8 reference ports, 0 matched: the open inter-connect),
  with `extract` proving all ten device instances are recognised. When the
  upstream gap closes, `regen.sh` regenerates the routed composition and the
  same pipeline gates DRC-clean + LVS-match for the follow-up slice. The
  LVS negative control (perturbed-W must report `device.property`) is not
  meaningful while zero devices match — it is deferred with the routing, and
  the pilot's per-kind negative controls continue to cover the
  parameter-compare liveness at device level.

## Files

- `regen.sh`, `tools/first_stage.py`: the recipe (imports the pilot's
  `schematic_cards` / `num_um` / `check_engine` — not forked)
- `gds/`: the three generated groups + the composed, labelled `first_stage.gds`
- `ref/first_stage.klt.spice`: the mechanically cut reference sub-netlist
- `extracted/first_stage.klt.spice`: klt's extraction of the composed cell
- `evidence/`: the `gen` / `compose` / `deck rules` / `drc` / `extract` / `lvs`
  envelopes and requests, plus the non-normative routed attempt
- `results.json`: per-run verdicts, the deck content hash, the composed
  GDS sha256 and its equality with the LVS envelope's `layout_sha256`

No cell was edited by hand to make anything pass, and no spec value was
changed.
